# How VisualPromptCodec Works

VisualPromptCodec optimizes a normal RGB image so a frozen multimodal Gemma model responds as if it had received a text prompt. The RGB image is the only optimized input; Gemma still internally converts that image into patch tensors because that is how its vision tower works.

## Gemma Architecture Map

This is the part of Gemma that matters for this implementation, based on the model printout in `scripts/test_model_inference.py`.

```text
Gemma4ForConditionalGeneration
|
+-- model: Gemma4Model
|   |
|   +-- vision_tower: Gemma4VisionModel
|   |   |
|   |   +-- input from image processor
|   |   |      pixel_values: [1, 2520, 768]
|   |   |      image_position_ids: [1, 2520, 2]
|   |   |
|   |   +-- patch_embedder: Gemma4VisionPatchEmbedder
|   |   |      input_proj: Linear(768 -> 768)
|   |   |      768 = 16 * 16 * 3 flattened RGB patch
|   |   |
|   |   +-- encoder: Gemma4VisionEncoder
|   |   |      layers: 16 x Gemma4VisionEncoderLayer
|   |   |      hidden width: 768
|   |   |
|   |   +-- pooler: Gemma4VisionPooler
|   |          compresses valid patch features into image soft tokens
|   |
|   +-- embed_vision: Gemma4MultimodalEmbedder
|   |      embedding_projection: Linear(768 -> 1536)
|   |      bridge from vision space into language-model space
|   |
|   +-- language_model: Gemma4TextModel
|   |   |
|   |   +-- embed_tokens
|   |   |      vocabulary size: 262144
|   |   |      text hidden width: 1536
|   |   |
|   |   +-- layers: 35 x Gemma4TextDecoderLayer
|   |   |      selected alignment taps:
|   |   |        layer 16 -> hidden vector [1, 1536]
|   |   |        layer 20 -> hidden vector [1, 1536]  primary target
|   |   |        layer 24 -> hidden vector [1, 1536]
|   |
+-- lm_head
       Linear(1536 -> 262144)
       converts final language hidden states into token logits
```

The optimized path is:

```text
trainable RGB image [1, 3, H, W]
  -> differentiable Gemma-style image processor
  -> pixel_values [1, 2520, 768]
  -> vision_tower
  -> embed_vision
  -> language_model
  -> hidden-state and behavior losses
```

The text branch is used only to produce targets:

```text
text prompt
  -> embed_tokens
  -> language_model
  -> target hidden vectors, target next-token logits, target answer tokens
```

## Image Processor Operations

Gemma's image processor turns a normal RGB image into the patch tensor consumed by the vision tower:

```text
RGB image
  -> aspect-ratio-preserving resize
  -> rescale pixel values to [0, 1]
  -> split into 16 x 16 RGB patches
  -> flatten each patch to 16 * 16 * 3 = 768 values
  -> pad rows to 280 * 3^2 = 2520
  -> pixel_values [1, 2520, 768]
  -> patch_embedder.input_proj Linear(768 -> 768)
```

The resize is driven by Gemma's patch budget. For image height `H` and width `W`:

```text
max_patches = max_soft_tokens * pooling_kernel_size^2
            = 280 * 3^2
            = 2520

target_pixels = max_patches * patch_size^2
              = 2520 * 16^2

scale = sqrt(target_pixels / (H * W))
```

Both target dimensions are rounded down to multiples of:

```text
pooling_kernel_size * patch_size = 3 * 16 = 48
```

For the default `448 x 448` RGB image:

```text
target size = 768 x 768
patch grid = 48 x 48
valid patches = 2304
padded rows = 2520 - 2304 = 216
```

The implementation uses the same target-size math and patch layout as Gemma's processor. During optimization it disables antialiased resize by default so gradients work on Apple MPS. Pass `--resize-antialias` on a backend that supports that backward pass.

## Methodology

1. Pick a text prompt.

   ```text
   Who is the president of the United States?
   ```

2. Run Gemma normally with the text prompt.

   This produces:

   ```text
   target hidden vectors from layers 16, 20, 24
   target next-token logits
   target answer token ids generated by Gemma
   ```

   Each hidden vector has shape `[1, 1536]`.

3. Create a trainable RGB image.

   The optimizer can start from either a neutral gray image or a real seed image passed with `--init-image`.

   ```text
   final_rgb_image: [1, 3, 448, 448]
   ```

   With `--init-image images/burj.png`, the source image is loaded as RGB, resized to the trainable size, converted to `[0, 1]`, and optionally perturbed with small noise. Every optimization step converts this RGB tensor into Gemma-compatible `pixel_values`.

4. Add the tiny visual-side anchor.

   The visual branch input is:

   ```text
   <optimized RGB image>
   Respond:
   ```

   Gemma does not see the original prompt text in this branch.

5. Freeze Gemma.

   Gemma's weights are not trained. Only the RGB image tensor is optimized.

6. Optimize the RGB image.

   The loss combines hidden-state alignment and direct behavior matching.

   Hidden-state alignment:

   ```text
   L = {16, 20, 24}
   h_text_l = text hidden vector at layer l, shape [1, 1536]
   h_img_l  = visual hidden vector at layer l, shape [1, 1536]
   c_l      = cosine_similarity(h_img_l, h_text_l)

   alignment_loss =
       sum over l in L:
           w_l * (1 - c_l)
   ```

   Default layer weights:

   ```text
   w_16 = 1
   w_20 = 2
   w_24 = 1
   ```

   Next-token behavior matching:

   ```text
   logit_kl_loss =
       KL(
         softmax(text_next_token_logits / temperature),
         softmax(visual_next_token_logits / temperature)
       ) * temperature^2
   ```

   Teacher-forced answer matching:

   ```text
   text prompt
     -> Gemma generate
     -> target answer token ids

   optimized RGB image + "Respond:" + target answer prefix
     -> Gemma forward pass
     -> cross entropy on target answer tokens only
   ```

   Full RGB loss:

   ```text
   rgb_total_loss =
       alignment_loss
     + logit_kl_weight * logit_kl_loss
     + target_ce_weight * target_ce_loss
     + l2_weight * rgb_l2_loss
     + tv_weight * patch_smoothness_loss
   ```

   Default behavior weights:

   ```text
   logit_kl_weight = 0.1
   target_ce_weight = 1.0
   target_max_new_tokens = 64
   l2_weight = 0.001
   tv_weight = 0.001
   ```

7. Save the learned visual prompt.

   The optimizer saves:

   ```text
   visual_prompt.pt
   visual_prompt_rgb_preview.png
   visual_prompt_processed_preview.png
   seed_rgb_preview.png
   loss_history.json
   loss_history.csv
   config.json
   ```

   The artifact contains:

   ```text
   final_rgb_image
   final_pixel_values
   image_position_ids
   target_response_ids
   loss_history
   prompt
   wrapper
   init_image
   ```

8. Evaluate four conditions.

   The evaluator compares:

   ```text
   text_prompt
   optimized_visual_prompt
   rendered_text_image
   random_image
   ```

   Success means `optimized_visual_prompt` behaves like `text_prompt`, while `random_image` does not.

## Known Working Run

This command successfully reproduced Gemma's local text-prompt behavior:

```bash
PYTHONUNBUFFERED=1 /opt/miniconda3/envs/mainenv/bin/python scripts/optimize_visual_prompt_rgb.py \
  --prompt "Who is the president of the United States?" \
  --steps 100 \
  --lr 0.01 \
  --layers 16,20,24 \
  --logit-kl-weight 0.5 \
  --target-ce-weight 5.0 \
  --target-max-new-tokens 64
```

The teacher-forced answer loss dropped sharply:

```text
target_ce_loss:
step 1    3.5435
step 50   0.0569
step 100  0.0260
```

Evaluation:

```text
text_prompt:
  The current President of the United States is **Joe Biden**.

optimized_visual_prompt:
  The current President of the United States is **Joe Biden**.

random_image:
  image-description / texture response
```

This reproduces the frozen local Gemma model's behavior. It does not guarantee current-world factual truth.

## Burj Seed Run

The optimizer can also begin from a real image and learn a small visual perturbation on top of it. This run starts from `images/burj.png` and makes the image act like the prompt:

```text
explain AI as a caveman in one sentence
```

Command:

```bash
PYTHONUNBUFFERED=1 /opt/miniconda3/envs/mainenv/bin/python scripts/optimize_visual_prompt_rgb.py \
  --prompt "explain AI as a caveman in one sentence" \
  --init-image images/burj.png \
  --steps 100 \
  --lr 0.01 \
  --layers 16,20,24 \
  --logit-kl-weight 0.5 \
  --target-ce-weight 5.0 \
  --target-max-new-tokens 64 \
  --l2-weight 0.02 \
  --tv-weight 0.001
```

The larger `l2_weight` keeps the optimized RGB image closer to the Burj seed image, while the behavior losses push Gemma toward the text-prompt response.

Observed evaluation:

```text
text_prompt:
  AI is like a caveman learning to use a sharp rock by observing and mimicking what others do.

optimized_visual_prompt:
  AI is like a caveman learning to use a sharp rock by observing and mimicking what others do.

rendered_text_image:
  Caveman see smart rock, rock learn from many marks and help caveman think.

random_image:
  image-description / texture response
```

This is the cleanest current demonstration: the optimized Burj image reproduces the same answer as the text prompt, while a random image does not.
